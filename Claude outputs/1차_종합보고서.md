## 1. 프로젝트 개요

### 1.1 배경 및 목적

전기버스/전기상용차용 배터리팩을 조립하는 공정 중 **배터리모듈 레이저 용접 설비**를 대상으로,
설비가 수집하는 공정 데이터(용접 출력 RealPower 등)를 분석하여 **용접 불량 및 설비 이상을
사전에 탐지**하는 예지보전(Predictive Maintenance) AI를 구축하는 것이 목표입니다. KAMP가
제공하는 실습 가이드북의 접근 방식을 먼저 재현한 뒤, 이를 기반으로 다변량 모델링·앙상블·학습
안정화 등 자체적인 개선을 단계적으로 시도했습니다.

**Speed**, **Length**, 그리고 시간 정보인 **GateOnTime**, **WorkingTime** 등을 함께 사용합니다.

이 두 유형의 차이는 본 보고서 전반에 걸쳐 각 모델의 강점과 한계를 설명하는 핵심 축이 됩니다.

## 2. 탐색적 데이터 분석(EDA) 핵심 발견

`01_eda.ipynb`에서 확인한 주요 사실은 다음과 같습니다.

**① 변수 간 강한 다중공선성 — "레시피" 구조.** 상관관계 히트맵 확인 결과 Speed, Length,
SetPower, GateOnTime은 서로 강하게 얽혀 있습니다. 이는 실제로 독립적인 4개 변수라기보다,
공정에서 미리 정해둔 소수의 **용접 "레시피" 조합**(설정값 세트) 중 하나가 매 용접마다 그대로
적용되기 때문입니다. 즉 데이터는 연속적인 값의 조합이 아니라 몇 가지 이산적인 레시피 그룹으로
군집화되어 있습니다. 이 발견은 이후 베이스라인 모델을 "전체 데이터 하나의 분포"가 아니라
**"레시피(SetPower)별로 조건부 분포를 따로 추정"**하는 방식으로 설계하게 된 핵심 근거가
되었습니다.

**② SetFrequency, SetDuty는 상수.** 데이터 전 구간에서 값이 변하지 않는 변수로 확인되어
분석에서 제외했습니다.

**③ RealPower 분포가 SetPower(레시피)별로 뚜렷하게 갈라짐.** `realpower_by_setpower.png`에서
확인할 수 있듯, 동일한 SetPower 조건에서는 RealPower가 좁은 범위에 밀집하지만 SetPower가
달라지면 분포 중심 자체가 이동합니다. 레시피를 무시하고 전체 데이터의 평균/표준편차만으로
이상을 판단하면, 정상적인 레시피 전환을 이상으로 오탐하거나 반대로 실제 이상을 정상 범위로
오판할 위험이 큽니다.

**④ 불량 테스트셋의 이상 발생 패턴이 서로 다름.** test03_NG는 짧은 순간에만 튀는 값이
나타나는 반면, test04_NG는 어느 시점부터 공정 자체가 다른 상태로 전환된 것처럼 지속적으로
비정상 값이 이어집니다. 이는 앞서 언급했듯 이후 모든 모델 비교에서 "고립형 이상 탐지력"과
"연속형(추세) 이상 탐지력"을 별도로 평가해야 하는 이유가 됩니다.

## 3. 방법론 및 결과

### 3.1 베이스라인 — 레시피 조건부 Z-score + 규칙 (`02_baseline_zscore.ipynb`)

EDA에서 확인한 레시피 구조를 그대로 활용한 통계적 방법입니다. 학습 데이터를 SetPower 값
기준으로 그룹화하여 그룹별 RealPower의 평균·표준편차를 구하고, 테스트 시점마다 **해당
레시피(SetPower)의 정상 분포를 기준으로 한 Z-score**를 계산해 임계값을 넘으면 이상으로
판정합니다. 여기에 SetPower=35처럼 학습 데이터에 존재하지 않는(또는 극히 드문) 레시피 값
자체를 이상 신호로 보는 규칙을 추가로 결합했습니다.

간단한 통계 기법임에도 두 테스트셋 모두에서 매우 안정적인 성능을 보였습니다(§4 비교표 참고).
레시피 구조를 명시적으로 반영한 것이 주효했습니다.

![베이스라인 예측 vs 실측](../outputs/baseline_prediction_vs_truth.png)

### 3.2 N-HiTS 단변량 — 딥러닝 시계열 예측 기반 이상탐지 (`03_nhits_model.ipynb`)

N-HiTS(Neural Hierarchical Interpolation for Time Series)는 과거 구간(인코더 길이)을 보고
다음 값을 예측하는 딥러닝 시계열 예측 모델입니다. RealPower의 과거 흐름만으로 다음 시점의
값을 예측하도록 학습한 뒤, **실제값과 예측값의 차이(잔차, residual)** 가 학습된 잔차 분포
기준으로 비정상적으로 클 때 이상으로 판정합니다(잔차 점수의 상세 정의는
`docs/도메인_배경지식.md` §5.2 참고).

레시피 정보를 전혀 사용하지 않고 오직 RealPower의 시계열 패턴만으로 학습했음에도 test04_NG(연속형
이상)에서는 베이스라인에 근접한 성능(F1 0.97)을 보였으나, test03_NG(고립형 이상)에서는
정밀도가 크게 떨어졌습니다(F1 0.31). 레시피 전환 시점의 정상적인 RealPower 급변을 모델이
"예측 실패"로 착각해 과탐(false positive)하는 경향이 원인으로 분석됩니다. 또한 이 노트북에서는
학습 중 **손실(loss)이 주기적으로 튀는 현상**이 관찰되었는데, 이는 §5에서 별도로 다룬
`06_nhits_stable_training.ipynb`의 개선 대상이 되었습니다.

![N-HiTS(단변량) 예측 vs 실측](../outputs/nhits_prediction_vs_truth.png)

### 3.3 N-HiTS 다변량 — SetPower를 공변량으로 추가 (`04_nhits_multivariate.ipynb`)

단변량 모델의 약점(레시피 전환을 이상으로 오인)을 보완하기 위해, 03번 모델에 **SetPower를
"미리 알 수 있는 공변량"(known covariate)** 으로 추가했습니다. 즉 모델이 예측 시점에 앞으로
적용될 레시피 값을 미리 알고 예측하도록 하여, 레시피 전환 자체를 예측 오차로 오인하지 않도록
설계를 개선한 것입니다.

의도한 대로 test03_NG의 정밀도가 개선되어 F1이 0.31 → 0.67로 크게 향상되었습니다. 다만
test04_NG에서는 소폭 하락(0.97 → 0.95)했는데, 이는 다변량 정보 추가로 모델이 더 유연해지면서
연속형 이상 구간에서도 일부 값을 "레시피가 바뀐 정상 패턴"으로 과도하게 흡수했기 때문으로
해석됩니다. 즉 레시피 정보 추가는 고립형 이상 탐지력과 연속형 이상 탐지력 사이에 트레이드오프를
만들었습니다.

![N-HiTS(다변량) 예측 vs 실측](../outputs/nhits_multivariate_prediction_vs_truth.png)

### 3.4 앙상블 — 베이스라인 × N-HiTS 결합 (`05_ensemble.ipynb`)

서로 다른 원리로 동작하는 두 모델(통계적 규칙 기반 베이스라인, 딥러닝 예측 기반 N-HiTS)의
예측을 결합하면 서로의 약점을 보완할 수 있는지 검증했습니다. 두 가지 결합 방식을 시도했습니다.

- **OR 결합**: 둘 중 하나라도 이상으로 판단하면 최종 이상 (재현율 우선)
- **AND 결합**: 둘 다 이상으로 판단해야 최종 이상 (정밀도 우선)

결과적으로 **AND 앙상블이 test03_NG에서 정확도·정밀도·재현율·F1 모두 1.0(완벽)**을 기록했습니다.
이는 N-HiTS 단독의 약점(레시피 전환을 이상으로 오탐)을 베이스라인이 걸러주고, 베이스라인
단독의 약점을 N-HiTS가 보완하며 두 모델의 "동시 합의"가 오탐을 효과적으로 제거했기 때문입니다.
반면 OR 결합은 두 모델의 오탐을 그대로 합쳐 오히려 두 테스트셋 모두에서 단독 모델보다 낮은
성능을 보였습니다.

이 노트북을 진행하며 한 가지 중요한 평가 방법론상의 유의점도 발견했습니다. test03_NG의 실제
이상 시점 중 하나가 N-HiTS의 **인코더 워밍업 구간**(예측을 시작하기 위해 필요한 초기 과거
구간으로, 이 구간은 점수 자체가 산출되지 않음)에 위치해 있었습니다. 03번 노트북의 평가에서는
이 구간을 암묵적으로 제외하여 재현율이 다소 낙관적으로(1.0으로) 보고되었을 가능성이 있음을
확인했고, 이번 노트북에서는 이를 명시적으로 "정상으로 간주"하고 처리하여 더 보수적이고
정직한 수치로 재평가했습니다.

### 3.5 N-HiTS 학습 안정화 실험 (`06_nhits_stable_training.ipynb`)

03번 노트북 학습 중 관찰된 "loss가 주기적으로 튀는" 현상을 진단하고 해결한 실험입니다.
원인은 세 가지가 복합적으로 작용한 것으로 분석되었습니다.

1. `limit_train_batches`로 매 epoch마다 전체 학습 데이터 중 **무작위로 다른 부분집합**만
   사용 — epoch마다 학습 데이터 구성 자체가 바뀌면서 손실 곡선이 요동
2. 학습률이 스케줄러 없이 고정되어 있어, 손실이 국소적으로 튀어도 자동으로 완화되지 않음
3. 검증셋 크기가 상대적으로 작아 검증 손실 자체의 변동성도 큼

이를 해결하기 위해 다음 세 가지를 적용했습니다.

- **무작위성 제거**: `limit_train_batches`를 없애 매 epoch마다 **전체 학습 데이터**를 사용
  (참고로 "고정된 무작위 부분집합만 반복 사용" 방식도 별도로 실험했으나, 오히려 검증 손실이
  epoch마다 단조 증가하는 심각한 과적합이 발생해 폐기했습니다)
- **학습률 스케줄러 + decay**: `Tuner.lr_find`로 학습률을 자동 탐색(단, 탐색 결과가 실행마다
  불안정하여 `[1e-3, 5e-2]` 범위로 안전하게 clip)하고, `ReduceLROnPlateau` 방식(patience=3,
  검증 손실이 3 epoch 동안 개선되지 않으면 학습률을 절반으로 감소, 최소 학습률 1e-5)을 적용
- **검증셋 확대**: 검증 구간 비율을 03번 대비 2배로 확대하여 검증 손실의 변동성을 완화

**학습 안정성은 뚜렷하게 개선**되었습니다. 검증 MAE가 3.723 → 1.038로 크게 낮아졌고, 검증
손실의 epoch 간 변동 범위(최댓값-최솟값)도 18.068 → 0.79로 약 23배 축소되었습니다.

![학습 손실 곡선 비교 (03번 vs 06번)](../outputs/nhits_stable_training_curve.png)

그러나 이 실험은 **예상치 못한 중요한 교훈**을 함께 남겼습니다. 학습 자체는 훨씬 안정되고
정확해졌음에도, 동일한 임계값(threshold=4.0)을 그대로 적용했을 때 이상탐지 성능은 오히려
**악화**되었습니다(test03_NG F1 0.31 → 0.15, test04_NG F1 0.97 → 0.96). 원인은 임계값이
"잔차 표준편차(sigma)의 배수"로 정의되어 있기 때문입니다. 모델이 더 정확해져 잔차의 표준편차
자체가 줄어들면, 같은 배수(threshold × sigma)가 만들어내는 실제 허용 오차 폭은 더 좁아집니다.
즉 **모델이 좋아질수록 같은 threshold 값이 상대적으로 더 엄격해져 정상적인 미세한 변동까지
이상으로 오탐**하게 된 것입니다. threshold를 6 이상으로 높여 재조정하자 test04_NG의 F1은
0.97 수준까지 회복되었으나, test03_NG는 threshold를 20까지 올려도 F1 0.49에 그쳐 완전히
회복되지는 않았습니다. 이는 단변량 모델이 레시피 전환을 이상으로 오인하는 근본적인 한계(§3.2)가
threshold 조정만으로는 해결되지 않음을 보여줍니다.

**핵심 교훈**: 모델의 예측 정확도(MAE, loss)를 개선하는 것과 이상탐지 임계값이 "여전히
적절한가"는 별개의 문제이며, 모델을 교체하거나 재학습할 때마다 threshold도 함께
재보정해야 합니다.

## 5. 핵심 인사이트

1. **레시피(SetPower) 구조를 명시적으로 반영하는 것이 가장 큰 성능 개선 요인이었습니다.**
   베이스라인의 조건부 Z-score, N-HiTS 다변량의 known covariate 추가가 모두 이 원리를
   활용했으며, 실제로 test03_NG 성능을 크게 끌어올렸습니다.

2. **원리가 다른 모델의 결합(AND 앙상블)이 각 모델의 개별 약점을 효과적으로 상쇄했습니다.**
   통계적 규칙 기반 모델과 딥러닝 예측 기반 모델은 서로 다른 유형의 오탐을 만들기 때문에,
   "둘 다 동의해야 이상"이라는 보수적 결합이 정밀도를 극적으로 높였습니다.

3. **딥러닝 모델을 개선(더 정확하게 재학습)해도 이상탐지 임계값은 자동으로 따라오지 않습니다.**
   06번 실험은 모델 자체는 명백히 개선되었음에도 고정 threshold 때문에 탐지 성능이 악화될
   수 있음을 보여주었습니다. 앞으로 모델을 바꿀 때마다 threshold 재보정 절차를 표준 워크플로우에
   포함해야 합니다.

4. **평가 방법론 자체의 함정에도 주의가 필요합니다.** 05번 노트북에서 발견한 "인코더 워밍업
   구간이 암묵적으로 평가에서 제외되는 문제"처럼, 모델 특유의 구조적 제약이 성능 지표를
   과대평가하게 만들 수 있습니다.

5. **고립형 이상(test03_NG)과 연속형 이상(test04_NG)은 서로 다른 능력을 요구합니다.** 한
   테스트셋에서의 개선이 다른 테스트셋에서의 개선을 보장하지 않으므로, 실제 배포 시에는 두
   유형의 이상을 모두 대표하는 검증 데이터로 균형 있게 평가해야 합니다.

## 6. 결론 및 향후 과제

현재까지의 실험에서는 **AND 앙상블(베이스라인 Z-score + N-HiTS)** 이 가장 신뢰할 수 있는
종합 성능을 보였습니다. 단순한 통계 규칙과 딥러닝 예측 모델을 함께 사용하는 것이, 어느 한
쪽에 의존하는 것보다 실제 제조 현장에서 더 안전한 선택이 될 수 있음을 시사합니다.

향후 진행하면 좋을 후보로는 다음이 있습니다.

- 06번에서 재보정이 필요하다고 확인된 threshold를 체계적으로 탐색해, 안정화 학습의 이점(낮은
  MAE)과 탐지 성능을 모두 취하는 최적점 찾기
- test03_NG 특유의 "고립형 이상"에 특화된 별도 탐지 로직(예: 순간 변화율 기반 규칙) 추가 검토
- 다변량 모델에 SetPower 외에 Speed, Length 등 추가 공변량을 포함했을 때의 효과 검증
- AND 앙상블에 안정화 학습된 N-HiTS(06번)를 재조정된 threshold와 함께 결합했을 때의 성능 검증
- 실제 KAMP 경진대회 제출 형식(리더보드 평가 지표, 제출 스크립트 규격)에 맞춘 파이프라인 정리
